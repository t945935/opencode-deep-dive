# 第 1 章　OpenCode 是什麼

## 本章目標

讀完本章後，你應能說明 OpenCode 與單純聊天工具的差異，辨認 Provider、Model、Session、Tool、Skill、MCP 與 Extension 的責任，並在不修改檔案的前提下完成第一次探索。

## 1.1 從「問答」到「可執行的代理」

聊天模型通常只產生文字；程式設計代理則需要觀察專案、採取行動、讀取結果，再決定下一步。OpenCode 將這個過程組織成代理迴圈（Agent Loop）。模型負責理解目標與提出下一個動作，OpenCode 負責上下文組合、工具執行、權限確認、工作階段保存與回應呈現。

這個區分很重要。模型不應被視為可以任意操作電腦的使用者；它提出工具呼叫，平台依政策判斷是否允許，工具執行後再回傳結果。權限、紀錄與停止點都在模型之外。

## 1.2 六個核心角色

- **Provider**：連線與認證的模型服務。
- **Model**：Provider 提供的具體模型。
- **Session**：保存一段工作的訊息、工具結果與狀態。
- **Tool**：讀檔、搜尋、執行測試或呼叫服務的受控介面。
- **Skill／Command**：可重用的工作流程與指示。
- **MCP／Extension**：將外部服務或客製能力接入核心。

它們可以組合，但不應混為一談。把「如何做程式碼審查」寫成 Skill，把「執行測試」做成 Tool，把「連接 Issue 系統」交給 MCP，會比將所有邏輯塞進一個巨大 Prompt 更容易測試與維護。

## 1.3 精簡核心與擴充優先

OpenCode 的核心價值不是內建最多功能，而是提供可替換的邊界。模型會更新，團隊可能更換 Provider；互動介面可能是 TUI、Web 或自訂 Client；外部資料也可能來自 GitHub、資料庫或公司內部服務。若這些能力都緊密耦合在核心，任何變更都會造成連鎖影響。

擴充優先設計要求每項能力說清楚輸入、輸出、權限、生命週期與失敗行為。這也使讀者能先用簡單設定開始，再逐步加入工具，而不必一開始理解整個平台。

## 1.4 第一次安全探索

在一個沒有機密資料的 Git 專案根目錄執行：

```bash
opencode --version
opencode run "只列出專案的主要目錄與測試指令，不要修改任何檔案"
```

先閱讀回應與工具紀錄，確認代理使用的工作目錄、模型及工具。若輸出不符合預期，不要立即授予更多權限；先縮小問題、檢查設定，再重新執行。

2. 將「產生 Commit 訊息」分類為 Prompt、Skill 或 Tool，並說明理由。
3. 設計一個只能讀取 `src/` 的探索任務，列出它不應擁有的權限。

## 小結

OpenCode 是協調模型與受控能力的代理環境。理解角色邊界，是後續設定模型、恢復 Session、建立 Tool 與設計 Extension 的基礎。
