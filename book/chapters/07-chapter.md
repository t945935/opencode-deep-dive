# 第 7 章　中斷、停止與重新開始

## 本章目標

中斷代理是正常的控制手段，不是例外。讀者將學會在危險操作、偏離目標、成本過高或服務失敗時停止，並安全地恢復或重新規劃工作。

## 7.1 何時應中斷

看到代理準備修改範圍外的檔案、執行不理解的命令、讀取機密、反覆重試或產生大量無關輸出時，應立即停止。先問「這個動作是否符合原始目標、是否可還原、是否需要我的批准」，不要因代理已經解釋一大段就放棄控制。

## 7.2 停止後的檢查

```bash
git status --short
git diff --stat
git diff
```

確認是否有部分寫入、未預期的刪除、背景程序、產生的暫存檔或測試資料。若工具執行了資料庫、部署或外部 API 操作，還要到服務端確認副作用；Git diff 不能涵蓋所有外部變更。

## 7.3 繼續、分支或重開

- **繼續**：目標不變、現有變更可接受，使用 `opencode --continue`。
- **指定 Session**：需要恢復較早工作時，使用 `opencode --session <id>`。
- **分支**：想嘗試不同方案而保留原歷史時，搭配 `--fork`，並以 Git 隔離檔案。
- **重開**：上下文已混亂、需求已改變或權限策略要重設時，建立新 Session。

恢復前先寫一段短摘要，明確指出「已完成什麼、不要重做什麼、下一個驗收條件」。

## 7.4 重試的界線

網路逾時可有限次重試；權限拒絕、語法錯誤或破壞性命令不應盲目重試。每次重試都應改變一個已知條件，並記錄結果。若切換 Provider 或 Model，重新驗證重要輸出。

## 章末練習

模擬一次測試修正任務：在代理提出修改計畫後中斷，檢查 Git 狀態，再以 Session 繼續。另建立一個分支方案，記錄兩種方案的測試與風險差異。

## 小結

停止、檢查、決定恢復方式，再繼續，是安全的代理工作循環。Session 能保存上下文，但只有人員與版本控制能決定哪些變更值得保留。
