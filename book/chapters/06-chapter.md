# 第 6 章　Session、訊息樹與上下文

## 本章目標

理解 Session 如何保存工作、訊息樹如何表達分支，以及上下文壓縮如何影響長任務。讀者將學會在繼續、分支與重新開始之間做選擇。

## 6.1 Session 是什麼

Session 不只是聊天紀錄，而是一次代理工作的可恢復邊界。它通常包含使用者訊息、模型回覆、工具呼叫、工具結果與相關狀態。工作是否可恢復，取決於這些內容是否被持久保存，以及工具本身是否可安全重做。

## 6.2 訊息樹與分支

若從某個歷史節點嘗試另一種方案，應建立分支而不是覆蓋原工作。分支讓兩組 Prompt、工具結果與 diff 可以比較；但分支不代表檔案系統自動隔離，因此仍要用 Git worktree、分支或暫存目錄隔離實際修改。

## 6.3 上下文容量

模型上下文由系統指示、專案規則、對話歷史、檔案片段與工具輸出組成。當內容接近上限，平台可能摘要或壓縮較早訊息。摘要若遺漏限制、測試結果或未完成事項，後續代理就可能重複工作或作出錯誤假設。

長任務每完成一個里程碑，就留下交接摘要：目標、已修改檔案、目前測試、未完成工作、已知風險與下一步。只讀取與當前任務相關的檔案，避免把整個 `node_modules`、建置輸出或大型日誌塞進上下文。

## 6.4 保存可恢復性

工具結果應包含命令、退出狀態與短摘要；重要產物應保存於可追蹤檔案。這樣即使模型切換或 Session 恢復，也能用檔案與測試重新建立事實，而非依賴記憶。

## 章末練習

建立一個包含三個里程碑的任務，在每個里程碑寫交接摘要。接著以不同方向建立分支，使用 Git diff 比較兩條路線，最後只保留測試通過者。

## 小結

Session 保存歷史，上下文決定模型當下看見什麼，Git 保存實際變更。三者各有責任，不能用聊天歷史取代版本控制。
