# 第 10 章　內建工具與自訂工具

## 本章目標

理解工具如何把模型輸出的意圖轉成副作用，並以最小權限設計第一個可測試的自訂工具。

## 10.1 工具合約

工具合約至少描述名稱、輸入型別、輸出格式、可能錯誤、所需權限與是否具有副作用。輸入應拒絕不合法路徑、未知選項與過大範圍；輸出應包含狀態、摘要與可供下一步使用的資料。

把「搜尋」與「修改」分成兩個工具，通常比一個能任意執行 Shell 的工具安全。破壞性操作提供 dry-run，寫入前顯示目標檔案並要求確認。工具應避免把 API Key、完整環境變數或不必要的大型日誌回傳給模型。

## 10.2 自訂工具生命週期

模型提出 Tool Call 後，OpenCode 先驗證格式與權限，再執行工具，最後把成功或失敗結果寫回 Session。工具本身不應假設模型一定會正確使用輸入；所有邊界檢查必須在工具端完成。

## 10.3 測試策略

先寫不需要模型的單元測試：合法輸入、空結果、逾時、權限拒絕、路徑穿越與部分失敗。再用固定 Prompt 做整合測試，確認模型能理解工具說明，但不要以模型文字取代工具結果驗證。

## 練習與小結

設計一個唯讀的 `list_tests` 工具，只能搜尋專案測試目錄，並在輸入含有 `..` 或絕對路徑時拒絕。工具越小，越容易審查與重用。
